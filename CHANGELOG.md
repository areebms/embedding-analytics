# Changelog

## 4.0

Two items on `main`'s old roadmap shipped this release — and one of them got walked back after being measured.

- **`/semantic-drift` replaces `/similarity` and `/similar-terms`.** Delivers what the roadmap called "diachronic similarity chart": one endpoint returns the query, five to ten comparative terms, and every requested book's score against each in a single round-trip. Comparative terms come from two selections that always run together: `stability`, the terms the books most agree belong near the query, and `instability`, the terms they least agree about — surfacing where a concept is contested rather than the closest synonyms. Both read each term's position within its own book's nearest-term neighbourhood rather than its raw cosine, so no statistic mistakes a book's overall similarity scale for disagreement, and both gate on two books having placed the term near the query at all. There is no `sort` request field — a mean-similarity sort and a slope/trend sort were both measured, shipped, and removed in turn, and the two-selections-always-together design that replaced them is now the whole surface.
- **A per-book score is now one of two models, and the row is flat.** The `BookLocalMeanSimilarity` envelope is gone. A score is a `DefinitionalAgreement` where a source book was nominated, or a `DefinitionalAgreementToCorpus` where none was — the same measurement taken against one peer or against every other requested book. The two are told apart by `n_books`, which the nominated form omits because it could only ever say `1`. Fields are renamed for the layer each names: `mean_similarity` → `mean_local_similarity` (the value), `similarity_ci` → `ci`, `count` → `occurrences`. *Definitional agreement* is the reading taken from that mean, and *definitional drift* the change in it across a corpus.
- **Scores carry two different intervals, and they are not comparable in width.** Against a nominated book the interval is still the spread across training seeds. Against the corpus the peers are now the unit of replication, so it reports how far the books sat from one another — which the old formula destroyed by averaging the peers before measuring any spread, and which is the more interesting number of the two. Values are unchanged to the last bit; only the intervals move, and corpus intervals widen by roughly 1.6x on the test corpus. Expect them wide at small corpus sizes: three peers leaves two degrees of freedom, which is the estimate being honest rather than a defect.
- **Pinecone: built, measured, and torn out of the read path.** The other roadmap item — "Pinecone for top-K similarity and lower API latency" — was built and used to back `/similar-terms` candidate generation, then measured against the real corpus. It failed every gate at this scale (V=639–1,651 terms/book is too small for ANN pruning to help), so `/similar-terms` was removed. `publish` still writes to Pinecone; nothing reads it yet (see What's next).
- **Cross-book alignment replaced by cross-book comparison.** `main` aligned book centroids into one shared corpus frame (`create_corpus_centroid.py`) for cross-author comparison. That frame is gone: at 200 dimensions the per-term cross-book rotation turned out to be underdetermined, so comparison now measures the similarity of each book's own local second-order embedding against the query, over a fixed 75-term neighborhood.
- **~4x faster similarity scoring** — every book's nearest-term ranking and pairwise comparisons now run as one batched matmul across all scored expressions, plus a cached sorted-array merge join for shared-term lookup, instead of one matmul per (book, expression) pair. A separate fix bulk-decodes a book's whole vector column in one pass instead of one `np.frombuffer` per term — profiling caught the per-term version thrashing the GIL badly enough that the concurrent loader ([Internals](functions/api/README.md#a-request-costs-the-slowest-book-not-the-sum)) was up to 8x *slower* than loading serially.
- **API image and cold start trimmed.** `gensim` and `scipy` sat in the API's `requirements.txt` unused by any API source file — dead weight from when the service still did in-process alignment math. Both are removed. `openai` is now imported lazily at its call sites in `describe.py` instead of at module scope; profiling found it responsible for roughly a third of `import main`'s cold-start cost, and only `/parse-describe` needs it.
- **Canonical structured logging** — one JSON line per request via a `ContextVar`-backed log context, replacing ad hoc `print`/logger calls; still fires on an unhandled exception so a 500 always leaves a trace.
- **Self-documenting, discriminated error contract** — `expression_absent`, `query_in_too_few_books`, and `term_resolution` each carry their own OpenAPI-visible schema instead of a bare message string.
- **Test-gated deploys with a coverage floor** — `deploy_lambdas.sh` now runs each service's suite inside a dedicated Docker test stage before any image is built; the API suite enforces 85% line coverage. Neither existed on `main`.
- **Internal book identity formalized as `BookIndex`**, and the API split into `app/core` / `app/list` / `app/search`, with `shared/` and `publish` refactored alongside it and per-service devcontainers added for `api`, `align-kvectors`, and `publish`.
